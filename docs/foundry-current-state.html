Foundry: current architecture + proposed additions

Foundry is currently a local, file-backed quality gate runner with structured evidence, scheduling, run indexing, and agent hooks. The remaining work is mostly hardening: fix watch mode, make explain less brittle, improve tests around Phase 2/3 surfaces, and consolidate stale planning docs.

Runner engine

runner.py executes gates, derives pass/warn/fail/needs_human, writes logs, supports fail-fast sequential mode and parallel mode.

Read this first: the architecture is usable today, but Phase 2 should not be called complete until watch mode is fixed.

Current product shape

  • Local gate runner, not a CI replacement.
  • Repo-local config in foundry.yaml.
  • Evidence stored under .foundry/runs/.
  • Global SQLite index under ~/.foundry/.

Working surfaces

  • run, doctor, latest, schedule.
  • init and repos.
  • Shell, Act, Dagger, Docker-wrapped gates.
  • Evidence JSON and run-index writes.

Next useful additions

  • Repair --watch.
  • Make passing explain keyless.
  • Broaden tests beyond run-index behavior.
  • Collapse stale plan/spec docs into one current brief.
