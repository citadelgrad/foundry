Act-first local gates for AI development

Foundry is the control layer, not another CI clone.

Use Act to run GitHub Actions locally. Add Foundry where AI development needs something CI does not provide: repo conventions, agent-readable failures, policy evidence, heavier review gates, and a clear stop/continue decision.

03 / Workflow

Why add Foundry to each step?

Because every step needs a decision, not another pile of logs. Foundry’s job is to turn local execution into evidence an agent and a human can both use.

What happens

Plan

Define the implementation goal, risk areas, and quality expectations before code changes begin.

Why Foundry

Convert the plan into gates

Foundry records which checks are required for this change: fast local checks, Act workflows, security review, mutation testing, or production verification.

What happens

Initialize the repo

scott-cc applies the AI-ready baseline: Makefile targets, AGENTS.md, CLAUDE.md, hooks, skills, and Beads.

Why Foundry

Make the baseline executable

`.init` should create the quality contract. Foundry gives that contract a single command and a consistent report format across repos.

What happens

Develop locally

The agent works inside repo conventions while hooks and Makefile commands catch cheap failures early.

Why Foundry

Summarize failures for agents

Foundry classifies failures into useful buckets: setup, lint, typecheck, test, build, workflow, policy, timeout, or environment.

What happens

Run PAS / Reckoner

PAS runs repeatable agent pipelines. Reckoner wraps real repos and PR workflows around them.

Why Foundry

Add a prove-it node

Foundry becomes the gate between pipeline stages: continue, retry, stop, create follow-up work, or allow Reckoner to open a PR.

What happens

Run GitHub Actions locally

Act executes GitHub Actions workflows locally with Docker/Colima.

Why Foundry

Wrap Act with policy

Foundry selects the workflow/event, manages inputs, captures artifacts, and turns Act’s output into a decision instead of raw terminal scrollback.

What happens

Run heavy gates

Mutation testing, fresh-eyes review, security review, dependency audit, and architecture review run when the change justifies slower checks.

Why Foundry

Control when expensive checks run

Foundry keeps heavy gates local, explicit, and repeatable. It also makes skipped gates visible, which matters almost as much as failures.

What happens

Apply gateway controls

The LLM gateway checks for secrets, unsafe prompts/tool calls, policy violations, security issues, and auditability gaps.

Why Foundry

Attach safety evidence

Foundry treats gateway output as part of the gate, not a side note. A run should say whether it was policy-clean, redacted, blocked, or risky.

What happens

Prepare for production

Deployment still needs health checks, rollback paths, runtime probes, monitoring, and post-deploy verification.

Why Foundry

Carry risk forward

Foundry reports what passed locally, what was skipped, and what production needs to verify. Local green is useful, not sufficient.

04 / Act-first

Use Act for the runner. Use Foundry for the judgment.

Act already runs GitHub Actions locally. Foundry should not rebuild that. Foundry should make local CI usable inside an AI development system.

Act handles

  • Running `.github/workflows/*.yml` locally
  • Docker-backed job execution
  • GitHub Actions event simulation
  • Reusing existing CI definitions
  • Homebrew install: brew install act

Foundry adds

  • Repo baseline enforcement from `.init`
  • Agent-readable failure summaries
  • Makefile fallback when no workflow exists
  • Policy/security/gateway evidence
  • Stop/continue decisions for PAS and Reckoner
$ foundry doctor
✓ act installed
✓ Docker/Colima available
✓ Makefile contract found: lint typecheck test build
✓ workflow found: .github/workflows/ci.yml

$ foundry run --event pull_request
✓ make lint
✓ make typecheck
✓ act -W .github/workflows/ci.yml pull_request
! fresh-eyes review skipped: not required by this plan

Decision: CONTINUE

06 / MVP

Build the boring slice first.

If the MVP cannot make one repo’s local quality gate clearer, it is not worth expanding.

PhaseBuildDo not build yet
1. Wrapper foundry doctor, foundry run, foundry explain. Detect Act, Docker/Colima, Makefile targets, workflows. Dashboard, distributed workers, YAML universe, cloud runners.
2. Evidence Write logs, JSON, Markdown summary, failure classification, stop/continue decision. Auto-fixing everything. Let agents consume the evidence first.
3. Integration Expose a PAS/Reckoner gate node and a scott-cc `.init` template. Deep coupling that makes Foundry unusable outside your stack.
4. Heavy gates Mutation testing, fresh-eyes review, security review, dependency audit. Running slow checks on every tiny change. Make them explicit.
